# Observations

Observation docs are run-specific checklists used to gather evidence.
They are not contracts and they are not specs.

Use them to record what to look for in artifacts so we can tell:
- what worked
- what failed
- what the current contract is missing
- how far the implementation is from `VISION.md`

Start with numbered files like `0001-<slug>.md`.

Current docs:
- `0001-dual-bank-memory-loop-checklist.md`
- `0002-memory-banks-and-injection-order.md`
